# Opportunity Discovery and Diversification

This requirement set is carried forward from the predecessor sales-and-marketing repository's diversification research.

## Principle

Echelon SHOULD avoid treating every idea as a separate consulting business. The system SHOULD identify reusable underlying capabilities and test multiple markets for those capabilities.

A recurring capability pattern is:

state + evidence + constraints + transitions + diagnostics + agents.

## Practice-level grouping

The predecessor research suggested these can largely collapse into:
- AI Engineering;
- Diagnostic Engineering;
- AI Governance & Evidence;

The system SHOULD permit alternative groupings as evidence changes.

## Initial commercial experiments

The predecessor suggested early testing around:
- AI Engineering Readiness;
- Agent-Ready Repository Assessment;
- Legacy Knowledge Risk;
- AI Technical Due Diligence;
- AI Technical Debt / Semantic Drift;
- AI Agent Governance;
- AI Development Cost Optimization;
- Compliance Evidence Architecture;
- AI Development Operating Model;
- Pivot / Opportunity Discovery.

The assessment -> diagnosis -> implementation -> training -> monitoring/governance -> software/tooling progression SHOULD be retained as a commercial hypothesis.

The system SHOULD explicitly test the broader positioning hypothesis that Echelon may be better understood as a diagnostic systems company than solely as an AI consultancy.
